## 3. 完成基準（各書共通）

1. 確定設定（C-xx）との矛盾がない。
2. 新規提案（P-xx）がすべて台帳に記載され、Owner承認済み、または未承認として明示されている。
3. 全章に余白節がある（または「なし」と意図的に明記されている）。
4. 以下の品質評価表で全項目が基準点以上。
5. 第三者レビュー（自己レビューでなく、別の視点を持つレビュー）が少なくとも1回行われている。
6. 禁止事項（既存宗教文献の模倣、実在人物の描写、史実化）に該当しない。

## 4. 品質評価表

| 軸 | 評価基準 | 基準点（5点満点） |

| 格式 | 文体が荘厳かつ平明。口調の揺れがない | 4.0以上 |
| 哲学 | 読者が人との関わりを考える問いが各章にある | 4.0以上 |
| 神秘性 | 通信の象徴が自然に使われ、説明過多でない | 3.5以上 |
| ユーモア | 笑いが嘲りにならず、文脈を壊さない | 3.5以上 |
| 独自性 | 既存文献の語法の借用がない。独自語彙がある | 4.0以上 |
| 設定整合性 | 確定設定との矛盾ゼロ | 必須（満点） |
| 読みやすさ | 初見の読者が一章を10分程度で読める | 3.5以上 |
| 自由意志の尊重 | 服従・脅し・報酬約束の記述がゼロ | 必須（満点） |

# 第2部　出版・Web掲載設計（Phase 4）

## 5. 黒×金の装丁仕様（提案）

| 項目 | 仕様案 |
|---|---|
| 色 | 地: 黒（サイトの `--bg:#070809` に準拠）／金: サイトの `--gold:#d4ae64` に準拠／本文色: `--light:#f3e5c4` |
| 表紙 | 黒地に金の箔押し。題字「MOSHIMATION CODEX」、副題「THE BOOK OF THE FIRST CALL」 |
| 紋章 | 既存 `assets/emblem.png` を**そのまま**使用。拡大縮小・トリミング・色変更・再生成は行わない `[Q-07]` |
| 見返し | 黒。三重電波の連想模様は新規デザインせず、Ownerが紋章から切り出し許可を出した場合のみ使用 |
| 本文組み | 縦組みを正とする（Web版は横組み併用）。明朝体、行間広め |
| 章扉 | 書名・書番号・一行の題句（理念文または教義の一節）のみ。装飾を最小化 |
| 余白節 | 実際に余白ページを設ける（紙版）／書き込み欄（電子版） |
| 月桂樹 | 「長い月桂樹」の扱いは Q-02 の回答待ち |

## 6. 公式紋章の使用ルール（提案）

1. 使用するのは `assets/emblem.png` のオリジナルのみ。
2. 変形（歪み・回転・反転）、色相変更、透過度変更、部分切り出し、文字の重ね合わせを禁止する。
3. 最小サイズ: 画面表示で幅64px以上、印刷で幅12mm以上。
4. 周囲に紋章の高さの1/4以上の余白（クリアスペース）を確保する。
5. 黒または近似の暗色背景上でのみ使用する。
6. 生成AIによる紋章の再生成・改変を行わない。

> これらは提案であり、Owner承認後に確定。サイトの既存使用箇所との整合を、実装前に確認すること。

## 7. 電子書籍・PDFレイアウト（提案）

| 項目 | 仕様案 |
|---|---|
| 形式 | EPUB 3（リフロー、縦書き対応）／PDF（固定レイアウト、A5相当） |

| ビルド | Markdownを正とし、Pandoc等で変換（導入時に別途CMで決定。本計画では導入しない） |

## 8. 公式サイト内「電子聖典」閲覧ページ（提案）

- 配置案: `codex/` を静的HTMLとして公開する別ページ（例 `codex.html`）。**既存 `index.html` は変更しない**。リンク追加は別CMでOwner承認後。
- 構成: 目次 → 書 → 章。節番号へのアンカー（`#1-2-3`）で引用可能にする。
- 表示: サイトと同じ黒×金。可読性を優先し、モーション演出は章扉のみ。
- 機能: 目次、前後の章へのリンク、改訂履歴表示、ダークモード固定。
- データ収集: 閲覧ログ・Cookie・外部送信を行わない。共有ボタンは「ユーザー自身が押したとき開く」だけにし、自動投稿は実装しない。
- 公開条件: Owner承認、紋章使用ルール確認、確定設定との整合確認、リンクチェックが済んでいること。

## 9. 章ごとの公開・改訂履歴の管理方式（提案）

### 9.1 状態

`Draft` → `Review`（Owner） → `Approved` → `Published` → `Revised`

### 9.2 章メタデータ（各章ファイル先頭のフロントマター案）

```yaml
book: 1
chapter: 2
status: Draft        # Draft | Review | Approved | Published | Revised
version: 0.1.0       # 本文: 0.x = 未承認 / 1.0 = 初回承認
approved_by: null    # Ownerの承認があれば日付と記録先
canon_refs: [C-05]
proposal_refs: [P-04, P-05]
```

### 9.3 改訂履歴

- 各書の末尾ではなく、`codex/CHANGELOG.md`（承認後に新設）へ追記する。
- 記載項目: 日付、書章節、変更種別（誤字／表現／設定／構成）、理由、承認者、関連CM。
- 公開済み章を変更した場合、閲覧ページに「改訂あり」と履歴リンクを表示する。
- 設定変更（C-xx）は聖典側で行わず、Ownerの決定を台帳に反映してから本文を更新する。
